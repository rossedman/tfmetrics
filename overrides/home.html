The problem

Terraform sprawl.
Nobody has counted it.

Which version of the EKS module are three hundred repos on? Which roots have no required_version? Answering means running terraform init everywhere or grepping and hoping. tfmetrics parses the HCL on disk and counts, the same way for every repo.

Core ideas

Three ideas.
Everything else follows.

tfmetrics sorts directories into roots and children, records what it finds as plain JSON, and scores the result against checks you can reweight.

Roots and children

Every directory with Terraform in it

A root has a backend, a cloud block or a configured provider. Everything else is a child module.

live/prod      root   s3
live/staging   root   cloud
modules/vpc    child  -

Facts, not scans

The contract between scan and aggregate

Each repo becomes one JSON file. Re-aggregate it with new weights or labels without cloning again.

"address": "github.com/acme/tf-iam",
"source_kind": "git",
"version": "",
"pinned": "none"

Hygiene score

0 to 100, from six weighted checks

Pinned modules weigh most. Weights are yours to change, and a check with nothing to check passes.

pinned                30 x 5/6
described             15 x 4/8
provider_constraints  15 x 2/5
required_version      15 x 1/2
typed_vars            15 x 3/4
parse_clean           10 x 4/5
                      => 65.3

Quick start

From install to metrics
in four commands.

You need Go and a directory with Terraform in it. No token, no cloud account.

{% include ".icons/material/book-open-page-variant-outline.svg" %} Full getting-started guide

  1. Install

    $ {{ install }}

  2. Scan a repo

    Writes one facts file.

    $ tfmetrics scan ./infra

  3. Read the report

    Inventory, score, pinning and diagnostics.

    $ tfmetrics explain facts/

  4. Write metrics

    Drop --offline to add version drift.

    $ tfmetrics aggregate facts/ --offline --sink openmetrics
